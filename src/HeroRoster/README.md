# Azeroth native hero roster

Nine source classes reuse the standard Megabonk character menu, its native buttons, selection, navigation and confirmation. The module does not build another character-selection menu.

`classes.json` is the original Azeroth Survivors v0.102.3 class catalog. Class icons must be installed in this plugin's `assets/Interface/Icons/` as bottom-up RGBA plus a `width height` `.size` file. PNG decoding is deliberately not used in the IL2CPP runtime.

Each runtime choice owns a private `CharacterData` clone from one common Amog engine shell, with an empty native class-stat list and an initialized `EPassive.None` passive. Native `PassiveAbilityMissing.Init/Tick/Cleanup` are verified no-op methods at RVA0x3321E0. The native inventory constructor and physics tick require a non-null passive; returning null would throw. Native active creation is suppressed only within a source `MyPlayer.StartPlayer` invocation, with a finalizer releasing the scope even on exceptions. Native weapon Tick/Use and grants beyond the mandatory first engine placeholder are blocked for source inventories. Common native movement, physics and spawning remain native. Source class health, race bonuses, spells, talents and visuals belong to their dedicated consumers of the bridge.

The menu temporarily receives a list of nine private choices during native `CharacterMenu.TryInit`; the original shared data list is restored in a finalizer. All21 old enum values resolve to the nine classes. Existing Amog14 resolves to Mage6. Runtime unlock/visibility/availability getters are scoped to private clone instances. Original data assets, achievements, purchases, currencies and skin collections are not modified by this module. Actual user selection follows the native configuration preference flow.

Public optional consumer contract: `AzerothHeroes.HeroBridge.SelectedClassId`, `ActiveClassId`, `ClassNameRu`, `StartingSpellId`, `ClassIds`, `GetClassNameRu(string)`, `ClassChanged`, `ActiveFormSpellId` and `SetFormForRuntime(int)`. The latter accepts0, Druid Bear9634/Cat768, or Priest Shadowform15473 as appropriate to the actual active class. Other class/form combinations are rejected. Active class is read from the actual player's private inventory data. `-azeroth-hero=<id>` selects an explicit source class; `-azeroth-test-battle` defaults to Mage only when that option is absent. Invalid class arguments fail explicitly.

Readonly `AzerothHeroes.HeroProbeApi.SnapshotJson` reports actual native buttons, names, icons, selection/start/confirm callbacks, inventory identity, passive type, active ability absence, stat modifier count and legacy aliases. `BatchProbe("focus"|"select:<id>"|"click:<id>"|"confirm:<id>")` requires both batch mode and `AZEROTH_LAB_HEADLESS_TEST=1`. Select invokes the real native button hover/A_Select path; click additionally invokes its native Unity Button.onClick; confirm invokes the actual native CharacterMenu.OnConfirmCharacter method. Describe is readonly. No save fixture is installed here; the root test orchestrator owns its existing guarded test-session save policy.

Compilation is not a runtime acceptance test. Root must verify nine actual menu buttons, all icons, each real selection/confirm, actual spawned class, native passive None and active ability null, with no native weapon attacks. Source form and actor visual checks are owned by the visual module.

0.1.1 menu presentation uses original rendered source-head portraits in native class buttons and the selected-hero information widget. Portrait lookup first uses the same canonical model root as visuals: `GameRoot/AzerothHeroAssets/<class>/portrait.rgba` plus `portrait.rgba.json` (`width`,`height`,`rowOrder=bottom-up`). It also accepts the plugin-local equivalent or `assets/portraits/<class>`. Glyph artwork remains separately accessible through `HeroBridge.GetClassGlyph`; `GetClassPortrait` returns the actual source portrait. No native character icon is substituted on missing art; explicit diagnostics/warnings show missing source portraits.

`classes.json` adds source-backed startingSpellName/startingSpellIcon/startingSpellSourceOffset from the class's original ability catalog. Selected hero UI shows that spell name and actual spell icon. The native passive widget is relabeled as source talents, uses the first source tree icon and lists the three original tree names; native character perks remain suppressed. These visual changes do not alter native selection/getter/purchase policies. Public selected/active race strings identify the agreed laboratory model preset (Human except Dwarf Hunter, Orc Shaman, NightElf Druid), not a claim of original class-default race.
